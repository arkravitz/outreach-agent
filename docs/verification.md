# Verification record

Automated tests use temporary SQLite databases and mocked model/mail/calendar/search transport boundaries. No live email is sent by tests. The full suite covers the twenty requested scenarios plus configuration/content approval invalidation, unknown-region blocking, deterministic Calendar booking, actual editor-file invocation, Gmail checkpoint failures/recovery/new-thread RFC matching, machine-readable DSNs, stale-state booking races, provider rate budgets, repeated-follow-up rejection and redrafting stale approvals. The Huey integration test runs a real consumer subprocess against a persistent SQLite queue and completes a durable digest job without network calls.

The independent read-only reviewer found three material gaps: new-thread reply matching, DSN status decoding and stale contact validation before Calendar insertion. Each was reproduced with a failing regression test and fixed, followed by a green whole-suite run. A concurrent-send test originally required all calls to return SENT; it now also allows the legitimate intermediate SENDING state while asserting exactly one provider send.

The offline lifecycle example uses synthetic research and fixture providers, loads the installed no-ai-slop files, queues a dry-run draft, exercises reviewed mock sending, reply dedupe, follow-up cancellation, interested classification, mock Calendar idempotency, proposal review and project completion. docs/dry-run-report.json is a saved report, explicitly labelled mock. It is not live LLM/editor or Google acceptance evidence.

Provider credentials were inspected by presence only using `pipeline doctor`: no standalone Google token, LLM key/models or Brave key was configured. No real search, LLM, Gmail draft/send/read or Calendar call was made. Existing desktop Calendar connectivity cannot be exported as daemon authentication. Production deployment and live-account acceptance require the operator's OAuth authorization, selected models/API keys, truthful sender identity/postal address/voice examples, reviewed recipient provenance/region and explicit live campaign approval.

Commands used: `pytest -q`, `ruff check src tests examples`, `ruff format --check src tests examples`, `python examples/dry_run.py --output docs/dry-run-report.json`, `pipeline init`, `pipeline doctor`, and a real Huey consumer subprocess. Final verification: 70 tests passed, Ruff lint passed and all 31 Python files passed formatting checks. The saved offline dry-run report records zero external emails and one mock email/event.
