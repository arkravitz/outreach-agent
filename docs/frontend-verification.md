# Frontend and low-cost provider verification

Implemented a bundled, responsive browser app over the existing Python domain services. No JavaScript production dependencies or build server. `pipeline serve --open` binds only to 127.0.0.1. The wheel includes HTML/JS/CSS/favicon and both default campaigns. Runtime settings persist in a restricted file and apply to newly created CLI/worker runtimes. Gemini and local Ollama share the JSON model interface; local Ollama needs no API key.

## Automated checks

- Complete Python suite: 90 passing tests at final verification, including existing workflow correctness, settings persistence/redaction, no-key local inference, daily call budgeting and telemetry, cloud-correspondence permission, CSRF/session/Host protection, OAuth client upload and callback URI/state, durable UI task status, local weight installation API contracts, worker ownership, concurrent preparation and stale campaign generation hashes.
- Chromium suite: five passing end-to-end scenarios against a temporary fixture host. Covers model setup, Gemini key masking, structured connection test, identity propagation, campaign editing, stale-draft regeneration, source/region review, explicit email approval into a pending queue, global pause and all eight views at 390-pixel width. No horizontal overflow and no JavaScript exceptions. All inference and Google operations in that suite are synthetic.
- Ruff lint/format, JavaScript syntax, Python compilation and wheel build checked. Screenshots were visually inspected on desktop and mobile. The desktop overview screenshot contains real empty workspace state; mobile setup screenshot is illustrative UI state with no real key entered.

Run Python tests with `pytest -q`. To repeat browser scenarios, install Playwright as a development tool (or point PLAYWRIGHT_MODULE_PATH at an existing installation), then:

```sh
PLAYWRIGHT_MODULE_PATH=/path/to/node_modules/playwright node tests/browser_scenarios.cjs
```

The browser script starts `tests/browser_fixture.py` on a temporary port/state directory, uses mocked HTTP model responses, creates no real mail/calendar actions, and shuts down/removes its fixture afterward. The main app has no dependency on Node or Playwright.

## Independent review and fixes

The reviewer found two Important issues: a stopped owned worker could appear external while its heartbeat remained fresh, and UI preparation could race a background preparation task and duplicate model calls. Both were reproduced with failing tests and fixed. Preparation now has a durable per-contact lease. Additional regression coverage rejects drafts if a campaign changes during generation. Browser QA also found and fixed form-name clobbering (`name="id"`): event routing now reads the actual form ID attribute, and the Chromium suite exercises the affected campaign/review/approval forms.

No material reviewer finding is deferred. This remains a local single-user operator app; public hosting/access control is outside this change.
