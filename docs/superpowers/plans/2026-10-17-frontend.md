# Pipeline frontend implementation plan

Execute inline under user's existing authorization to implement and make routine architecture decisions.

1. Test-first: persisted runtime settings, Gemini/Ollama presets, actual model listing/testing, daily call budgets/usage and no-key loopback LLM support. Files settings.py, providers.py, runtime.py, research.py, tests/test_settings.py and tests/test_provider_setup.py.
2. Test-first: local JSON API, session/CSRF/Host protection, masked credentials, OAuth browser flow, campaign/contact/message/CRM actions and worker supervision. Files web.py, web_api.py, worker_control.py, tests/test_web.py.
3. Implement bundled polished UI, onboarding forms, provider cost/usage explanation, real pipeline views and domain actions. Serve without a build step. Files src/pipeline/static/* and CLI serve entry.
4. Test browser flows on temporary state with mocked providers, verify responsive layout and accessibility basics, fix issues. Run full tests/lint/format and offline lifecycle demonstration. Independent review of access controls and outbound action boundaries.
5. Document launch, Gemini setup and credits, Ollama requirements, free URL imports, limits and which external setup must still happen in Google Console/Ollama.

Review focus: secrets never echoed; browser cross-origin requests cannot mutate state; cloud correspondence sharing is explicit; daily request cap applies across restarts; model tests do not send email; worker cannot start twice from the UI; approval/suppression/pause gates remain authoritative.

Completed: all five implementation/check/documentation steps. Final evidence: 90 Python tests, five Chromium scenarios, lint/format/compilation/build, and a real synthetic local-model qualification. No live Google or Gemini acceptance claim.
