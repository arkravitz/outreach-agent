# Pipeline local operator app

Extend the existing tested Python backend with a polished local browser app. User wants all setup and day-to-day operations visible; cost should approach zero using an existing computer. They have AI Studio/Gemini API credits and 16–32 GB RAM. Default model presets: Gemini (credits/API key) and local Ollama (no key). Keep the OpenAI-compatible adapter generic; no mandatory paid model, search subscription, database service, JavaScript build or frontend hosting.

Use Python's standard-library HTTP server bound exclusively to loopback, serving bundled HTML/CSS/JS and a same-origin JSON API. A process-scoped HttpOnly session cookie and CSRF header protect mutations; validate Host and Origin, refuse CORS, restrict request sizes, escape untrusted data and keep secrets out of JSON responses. Secrets live in mode-600 settings files in the existing state directory. UI state changes use existing Pipeline domain methods and send gates. No public deployment or new Site, because this UI manages local OAuth credentials and the single-host database.

Visual direction: quiet editorial control room, warm off-white canvas, ink sidebar, orange accent, compact tables, generous whitespace, visible status chips. Responsive layout. Navigation: overview, prospects, review inbox, conversations, campaigns, meetings/projects, activity, setup. Real empty states and disabled actions explain missing prerequisites. Persistent setup progress derives from configuration/validation, not decorative checkmarks. No fabricated business results.

Setup steps: choose Gemini/Ollama/custom endpoint; save key without echoing it; list models/test a synthetic request; enter sender identity/postal address/voice and bounded campaign settings; upload Google Desktop OAuth client JSON and connect account in the browser; select optional Brave discovery or free company-URL imports; set call budgets and discovery policy; validate readiness. Google Console account/project creation and installing Ollama/model weights require the user's computer/account; link exact instructions from the UI. Browser APIs cannot create those permissions silently.

Use JSON file settings read afresh by CLI/worker/UI, with environment variables taking precedence for existing deployments. Persist per-task model routing, optional cloud use consent for correspondence, daily request cap and request telemetry. Display actual known usage, not invented credit balances/costs. User-supplied token prices may estimate cost; default no dollar estimate. No automatic provider fallback that could unexpectedly incur charges or upload private mail.

An app-managed Huey child process can start/stop from the UI; heartbeat shows actual liveness and distinguishes external workers. Default worker off; start requires readiness. Network/provider tests use a synthetic prompt and explicit button; no email send as a connection test. Review approval queues actual sending and clearly says so. Sensitive scopes/pricing stay on existing gates. Autonomous mode requires a separate confirmation of exact campaign config hash; changing config invalidates authorization.

Test settings persistence/redaction, no-key local model support, Gemini-compatible request contract, daily budget enforcement, telemetry, local HTTP session/CSRF/Host checks, API mutations/approval preservation, worker status, OAuth state/callback mocks and end-to-end browser setup/empty state flows. Run the existing backend suite. Never use real email or billable model calls in automated tests.
